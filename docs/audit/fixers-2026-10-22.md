# Fixers and the reviewed release (22 Oct 2026, night)

The owner's plan for the 236 cards the held-card audit read ("docs/audit/held-audit-2026-10-22.md"):

1. stop our fixers making right figures wrong, with tests built on these cards;
2. fix the commonest false holds, each with a before-and-after check over stored cards and an independent sample;
3. release the 100 cards, then the 108 with their named points removed, through the existing release path.

## 1. Unit fixer

The audit found the unit fixer turning right figures wrong. The new guard, `grounding._ReadAtUnit`, works like this:

- If a card figure is already the right crore reading of a figure the filing prints, the fixer leaves it alone.
- The unit used for that reading is the figure's own unit word if it has one ("Rs. 26,265.71 Lakh").
- Failing that, it is the unit declared last before the figure on its page, within 8,000 characters.
- On a page that declares no unit, it is the document's unit, but only when the whole document uses a single unit.

Two unit words are now read: `Crs` as crore and `(₹ mm)` as million.

**Before and after over the stored fixes.** There are 47 unit fixes on the held and flagged cards. Two independent reviewers judged each one blind against its PDF:

- 33 were right.
- 12 made a right figure wrong.
- 2 were wrong both before and after the fix.

| verdict | still fixed | now blocked |
|---|---|---|
| right fix (33) | **33** | 0 |
| wrong fix (12) | 3 | **9** |
| wrong either way (2) | 2 | 0 |

A first version of the guard would have blocked Goodyear's right fix, 1,528.7 to 152.87. That annual report uses lakh, million, thousand and billion, so its "15,287" (in lakh) read as million matched the wrong 1,528.7. The one-unit rule fixed this.

## 1b. Change fixer

A percentage change that the filing itself prints is never recomputed. Among the stored cards, this changes only one: Greenply's MDF revenue stays at "+39.6% YoY" (the deck says "an 39.6% increase"). It had been recomputed to -70.2% from the quarter and full-year figures. No other stored recomputation prints its original percentage, so none of the rest change.

## 3. Reviewed release

`release-reviewed --plan <file>` is run through `release-held.yml` with its `plan` input, and `dry_run` comes first. It writes through the same `cards_release_pruned` statement as the quote-only prune. That statement writes only a card that is still held or flagged, and never one the owner marked Wrong.

- It takes off whole list items only, and each must still read as the reviewer saw it. A headline, takeaway or sentence is never cut.
- D20 still applies: a held results card stays held when a published card already owns its quarter.

The plans:

- `docs/audit/live/release-2026-10-22-a.json`: the 100 cards cleared as they stand. In the dry run over the stored snapshot, 99 are released and 1 is kept because its quarter already has a card.
- `docs/audit/live/release-2026-10-22-b.json`: the 108 cleared without named points. An independent agent mapped each named point to whole items. 64 are released and 44 kept, for these reasons:
  - 37: the fault is in the headline, takeaway, core catalyst or timeline line.
  - 6: the review asks for a rewrite.
  - 2: the point names a deal value, which is not a list item.

The 44 kept, and the 28 KEEP_HELD cards, are re-run after the step-2 fixes.
