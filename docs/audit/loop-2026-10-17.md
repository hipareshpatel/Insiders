# The 2026-10-17 loop: twenty filings, read five times

The owner's method (2026-10-17): work card quality in rounds of ten to twenty, audit the round, find
the root cause of each defect, fix it, then read the **same filings again**. A fresh sample would
measure the fix and a change of sample at once.

The twenty are round 1's WRONG cards, chosen by `scripts/rerun.py --from-audit docs/audit/round-1.json
--verdict WRONG --limit 20`: a stratified sample that covers every error class before it doubles up on
any, because the rarest classes sit on single cards. They span 2025-01-23 to 2026-08-11, eight
companies, nine event types and all ten classes. `process --news-ids` reads only them. The model
weights were left alone between rounds, or the comparison would measure the models.

## What each round changed

| Round | Fixes added |
|---|---|
| 2a | none - the starting point, on the code as it stood after reading order and the quote contract |
| 2b | the XBRL override no longer writes the quarter's figure under the year's label; a change of more than a thousand percent is read whole; the deterministic fixers run on a card adopted from the second provider, and the record beside a card describes the card that was published |
| 2c | a bare label follows the period the card is about; a figure replaced from another period loses the change that belonged to the one it replaced; a quoted row is read at a unit |
| 2d | the unit comes from the filing rather than the XBRL table put in front of it; a day of the month is not a figure; how a card quoted the filing no longer holds it back by itself |
| 2e | one rule for both quote checks, rather than two that had drifted apart within a day |

## What it cost and what it bought

Nothing here is a verdict on whether a card is right - that is audit round 2, still to run. These are
the counts the code itself produces: how many cards were written, how many were held back from the
feed, and what each hold was for. A held card is not lost: it goes to the review queue.
